# Brevo 선정 안내 메일 연결

브랜드가 새 지원자를 선정하면 DB에 안내 메일을 함께 저장합니다. 서버는 30초마다 대기 메일 한 건을 처리합니다. 수신자마다 별도 메일을 발송하며 다른 인플루언서의 주소를 공개하지 않습니다. 선정 안내는 한국어·영어를 함께 제공합니다. 참여 내역 버튼 대신 로그인 후 접근하는 참여 내역 URL을 본문에 넣습니다.

## 1. Brevo 계정 및 발신 주소 준비

1. https://www.brevo.com 에서 계정을 만들고 이메일 인증 및 계정 검토를 완료합니다.
2. Settings의 **Senders, Domains & Dedicated IPs**에서 발신 주소를 등록합니다. 메뉴 이름은 언어/서비스 변경에 따라 달라질 수 있습니다.
3. 가능하면 소유한 도메인의 `notifications@도메인` 주소를 사용하고, Brevo에서 제공하는 DNS 레코드로 도메인을 인증합니다. DNS 값은 Brevo 화면에 표시된 값을 그대로 사용합니다.
4. 기존 Gmail은 `EMAIL_REPLY_TO`로 지정해 답장을 받습니다. Gmail을 발신 주소로 쓰면 Gmail 도메인의 DNS를 직접 인증할 수 없으므로 권장하지 않습니다. 발신 이메일 인증과 도메인 인증은 별개입니다.
5. **SMTP & API → API Keys**에서 서울센트용 API 키를 만듭니다. SMTP 키가 아닌 API 키가 필요합니다. 키를 채팅, GitHub, 명령 기록에 넣지 마세요.

## 2. Render에 연결

Render → 서울센트 Web Service → **Environment → Add Environment Variable**에서 아래 항목을 등록하고 저장/재배포합니다. 실제 발신 주소와 키는 Render에만 입력합니다.

| 변수 | 값 |
|---|---|
| `EMAIL_PROVIDER` | `brevo` |
| `BREVO_API_KEY` | Brevo에서 발급한 API 키 (비밀 값) |
| `EMAIL_FROM` | Brevo에서 승인·인증한 발신 이메일 |
| `EMAIL_REPLY_TO` | 답장받을 Gmail 주소 |
| `APP_ORIGIN` | `https://seoul-scent.onrender.com` |
| `EMAIL_DAILY_LIMIT` | 처음에는 `100` 권장, 필요하면 `300` |

발신 주소 변수에는 이름 없이 이메일 주소만 입력합니다. API 키는 SMTP 비밀번호나 Gmail 비밀번호가 아닙니다. 설정을 파일로 저장하거나 Git에 커밋하지 마세요. 클라우드 개발 환경에는 실제 운영 키가 없어도 개발/테스트가 가능하므로 별도로 등록할 필요가 없습니다.

Brevo 무료 플랜은 알려진 기준으로 하루 300통이며 가입 시 최신 한도를 확인하세요. 서버의 `EMAIL_DAILY_LIMIT`는 최근 24시간 동안의 **발송 시도 횟수(재시도 포함)** 제한이며 Brevo 계정 전체의 발송 한도를 늘리지 않습니다. 다른 앱의 발송도 Brevo 한도를 사용하므로 여유를 두세요.

## 3. 실제 수신 확인

1. 운영사 계정의 통합 대시보드에서 **선정 안내 메일 → 연결 설정 완료**를 확인합니다. 이것은 환경 변수 형식과 존재 여부 확인이며 API 키 유효성/발신 인증을 검증한 결과는 아닙니다.
2. 본인이 접근할 수 있는 이메일로 테스트 인플루언서를 가입하고, 테스트 캠페인에 지원합니다.
3. 브랜드 계정으로 해당 인플루언서를 선정합니다. 최대 30초 뒤 발송이 시작됩니다.
4. 운영사 대시보드를 새로고침해 상태를 확인합니다. **서비스 접수 완료**는 Brevo API가 접수한 상태입니다. 실제 받은편지함과 스팸함, Brevo Transactional 로그를 모두 확인해야 도착을 검증할 수 있습니다.
5. 링크를 눌러 로그인 후 본인의 참여 내역/배송지 등록 화면으로 연결되는지 확인합니다. 영어 캠페인명이 등록되어 있으면 영어 안내에도 해당 이름이 사용됩니다.

현재 구현 범위는 **선정 안내**입니다. 배송, 수정 요청, 승인, 마감 알림의 이메일 발송은 아직 연결하지 않았습니다. 내부 알림은 기존대로 제공됩니다.

## 실패/운영 정책

- `EMAIL_PROVIDER`가 없거나 `none`이면 새 선정에 대해 메일을 만들지 않습니다. 기존 선정자에게 일괄 발송하지 않습니다.
- `brevo`를 켠 뒤 필수 설정이 빠져 있으면 메일은 DB에서 대기합니다. 키를 연결하면 대기 중인 메일이 처리됩니다. 설정을 끄면 발송이 멈추지만 기록은 남습니다.
- 네트워크 오류, 일시적인 서버 오류, 인증/한도 오류는 간격을 늘려 최대 5회 시도합니다. 영구적인 요청 오류는 즉시 실패로 표시합니다.
- `provider_http_401`/`403`: API 키, 발신 권한, 계정 검토 상태를 확인합니다. `429`: Brevo 계정 한도를 확인합니다. `400`: 발신/수신 주소와 Brevo 로그를 확인합니다.
- 운영사 대시보드에서 실패한 메일을 재시도할 수 있으며 운영 이력이 남습니다. 성공한 메일은 재발송 버튼을 제공하지 않습니다.
- DB의 선정 이벤트 키로 반복 선정 요청의 중복 생성을 방지합니다. 다만 외부 서비스가 접수한 직후 네트워크가 끊기거나 서버가 종료되면 결과를 확인하지 못해 재시도 시 중복 메일이 도착할 수 있습니다. 이런 경우 Brevo 로그를 먼저 확인하세요.
- 배송지·연락처·비밀번호를 메일에 넣지 않습니다. API 키와 공급자 오류 응답 본문을 서버 로그/대시보드에 노출하지 않습니다. 수신 주소와 발송 내용/상태는 기존 DB 및 백업에 보관됩니다.
- 대기/발송 기록은 Render 영구 디스크 DB에 저장됩니다. 자동 접수 상태는 실제 배달/반송 상태와 구분합니다. 반송 웹훅은 현재 연결하지 않았습니다.

## 개발 검증

`npm run typecheck`, `npm test`, `npm run test:browser`로 검증합니다. 테스트는 외부 공급자 응답을 모의 처리하며 실제 메일을 발송하지 않습니다. API 키가 없으면 서버 메일 워커는 비활성 상태입니다.
