# Seoul Scent

브랜드와 인플루언서의 캠페인 협업 관리 도구입니다. Node.js 24, Hono, SQLite로 구현했습니다.

## 구현한 기능

- 계정: 브랜드·인플루언서 가입, 별도 운영사 발급, 로그인·로그아웃, 역할별 화면/API 권한
- 마이페이지: 브랜드명·담당자명/성함·연락처·이메일·비밀번호 수정, 현재 비밀번호 확인, 중복 이메일 차단, 인증정보 변경 시 다른 기기 세션 해제
- 캠페인: 제품·웹 링크·인원·유/무가·활동비·가이드라인·모집 시작/마감·초안/최종 마감 등록, 검색, 모집 마감, 종료
- 지원: 2차 활용·고화질 원본 제공 필수 동의, 각 항목별 동의와 버전/시각 저장, 선정 후 배송지 등록, 중복 지원 방지
- 선정: 팔로워·티어·SNS 프로필 확인, 선정·반려, 모집 인원 제한, 제재 중 지원/선정 차단
- 배송: 배송지 XLSX 다운로드, 송장 XLSX 일괄 업로드, 개별 등록, 인플루언서 송장 확인
- 콘텐츠: HTTP/HTTPS 웹 링크 초안 제출, 공개 권한 확인 체크, 수정 요청·재제출 마감일·재제출, 승인, SNS 최종 제출
- 완료: Best·브랜드 확인 조회수 기록, 중복 완료 차단, 참여 횟수/누적 조회수·티어 갱신, 결과 XLSX
- 티어: 완료 0개 미등급, 1~9개 브론즈, 10~49개 실버, 50~99개 골드, 100개 이상 플래티넘. 조회수 조건 없이 완료 횟수로 승급하며 기존 노쇼 강등은 유지합니다.
- 활동증명서: 브랜드가 완료 처리한 캠페인 1개 이상이면 내 프로필에서 발급. 한국어·영어 증명서를 인쇄/PDF 저장할 수 있으며 증명서 번호·발급일·이름·완료 활동 목록을 발급 당시 정보로 보관합니다. 본인 및 운영사만 조회합니다.
- 이력/알림: 링크 버전과 피드백 타임라인, 내부 자동 알림, 마감 하루 전 알림, 읽음 처리
- 선정 메일: Brevo API 연결, 한국어·영어 안내, DB 발송 대기열·재시도·운영사 발송 현황. 설정 방법은 [EMAIL_SETUP.md](EMAIL_SETUP.md)를 참고하세요.
- 운영: 통합 대시보드, 계정·참여 이력 검색, 정책 변경, 사유를 기록하는 제재 해제, 운영 변경 기록
- 데이터 보호: 비밀번호 scrypt 해시, 서버 세션·HttpOnly 쿠키, 로그인 실패 제한, 교차 출처 차단, HTML 이스케이프, 업로드/압축 해제 크기 제한
- DB 백업: SQLite 온라인 백업과 무결성 검사

## 로컬 실행

기존 격리 체크아웃을 사용합니다. 별도 Git worktree는 필요하지 않습니다.

```bash
cd /workspace/ygsc-beauty/seoul-scent
npm ci --include=dev --cache /workspace/.npm
npm run dev
```

`npm start`는 watch 없이 실행합니다. 기본 포트는 3000이며 `PORT`로 바꿀 수 있습니다. `/register`에서 계정을 만든 뒤 브라우저로 사용하세요. `/health`에서 DB와 HTTP 응답을 확인합니다.

## 운영사 계정 생성

기본 계정/비밀번호는 제공하지 않습니다. 서버 관리자가 안전한 터미널에서 다음 명령을 실행합니다. 비밀번호는 숨김 입력하며, 실제 값을 명령 이력·문서·로그에 남기지 않습니다.

```bash
read -r -p '운영사 이메일: ' ADMIN_EMAIL
read -r -s -p '운영사 비밀번호 (12~128자): ' ADMIN_PASSWORD
export ADMIN_EMAIL ADMIN_PASSWORD
npm run admin:create
unset ADMIN_EMAIL ADMIN_PASSWORD
```

기존 이메일의 역할/비밀번호를 덮어쓰지 않습니다. 필요하면 `ADMIN_NAME`으로 표시 이름을 지정하세요.

## 기본 사용 순서

운영사의 **등급관리 → 인플루언서 엑셀 등록**에서 Google Form 지원서 XLSX를 검토하고 등록할 수 있습니다. 이름·이메일로 계정을 생성하고 가능한 연락처·SNS 링크·팔로워 수를 가져옵니다. 파일 중복/기존 이메일은 건너뛰며 기존 계정의 비밀번호·역할을 덮어쓰지 않습니다. 임시 비밀번호는 운영사가 입력하고 서버에는 scrypt 해시만 저장합니다. 신규 계정은 첫 로그인에서 12~128자의 새 비밀번호를 설정해야 다른 기능을 사용할 수 있습니다. 연락처/SNS/팔로워 수를 정확히 해석하지 못한 경우 본인이 프로필을 확인·저장해야 지원할 수 있습니다. 엑셀 응답은 캠페인 지원·2차 활용 동의·활동 완료로 간주하지 않습니다. 원본 파일은 저장소에 넣지 않습니다.

1. 브랜드 가입(브랜드명·담당자명·연락처·이메일·비밀번호) → 캠페인 만들기
2. 인플루언서 가입(성함·연락처·이메일·비밀번호) → 내 프로필에 SNS 계정 링크·팔로워 수 저장 후 지원 가능
3. 캠페인 찾기 → 가이드 확인 → 필수 동의 후 지원
4. 브랜드 → 캠페인 참여자 선정 → 인플루언서가 참여 내역에서 수령인·연락처·우편번호·주소·상세주소 등록 → 브랜드 송장 등록 또는 XLSX 업로드
5. 인플루언서 → 내 캠페인 → 검수용 초안 링크 제출 (검수 없는 캠페인은 최종 링크로 바로 진행)
6. 브랜드 → 검수 → 수정 요청 또는 승인. 수정 요청 시 새 재제출 마감일을 지정합니다.
7. 인플루언서 → 승인 후 SNS 게시물 URL 제출
8. 브랜드 → 조회수/Best 확인 → 활동 완료. 모집 마감·미처리 지원자/진행 활동 정리 후 캠페인 종료
9. 운영사 → 통합 현황/이력 확인, 정책 관리

브랜드·인플루언서는 왼쪽 **마이페이지**에서 계정 정보를 수정합니다. 브랜드는 브랜드명·담당자명, 인플루언서는 성함을 수정할 수 있고 모두 이메일·연락처·비밀번호 변경을 지원합니다. 현재 비밀번호 확인이 필요하며, 이메일/비밀번호 변경 시 다른 기기의 세션을 해제합니다. 기존 캠페인에 저장된 배송지·연락처는 계정 수정으로 덮어쓰지 않습니다.

신규 캠페인 지원에는 내 프로필의 연락처·HTTP/HTTPS SNS 프로필 링크·팔로워 수 저장이 필요합니다. 팔로워 최소 인원 조건은 추가하지 않았습니다. 링크 형식 검증은 실제 SNS 계정의 소유 인증을 대신하지 않으며 브랜드가 선정 시 확인합니다. 기존에 지원/선정된 참여 내역은 그대로 유지합니다.

모든 데이터는 실제 입력으로 생성합니다. 브라우저 테스트는 별도 임시 DB에서 가상 데이터를 만들고 종료 시 삭제합니다.

## 마감과 제재 정책

- 날짜는 **한국 시간 해당 날짜 종료(다음 날 00:00)** 기준입니다.
- 서버 시작, 60초 간격 작업, 로그인한 사용자의 업무 API 요청 때 마감을 확인합니다. 서버가 꺼져 있으면 실행되지 않으며, 재시작 시 누락된 처리를 수행합니다. 상태 전환은 마감 이후 최초 검사 시점에 반영됩니다.
- 초안 검수가 없는 캠페인은 선정/배송 단계에서도 최종 마감을 기준으로 검사합니다. 검수가 있는 캠페인은 선정/배송 단계에서 초안 미제출, 수정 요청 단계에서 재제출 미이행, 승인 후 최종 URL 미제출을 노쇼 처리합니다.
- 이미 초안 또는 최종 URL을 제출한 검수 대기자는 브랜드 검수 지연만으로 노쇼 처리하지 않습니다.
- 기본: 노쇼당 티어 1단계 강등, 제출 마감 시점부터 30일 신규 지원 제한, 누적 2회 영구 제한. 운영 정책에서 변경할 수 있습니다.
- 티어는 완료 횟수와 **브랜드가 직접 확인한 누적 조회수**를 모두 충족해야 올라가고, 누적 노쇼 강등을 함께 반영합니다. 기본 T2=3회, T3=10회/1만 조회, T4=20회/10만 조회입니다.
- 정책 변경 시 티어를 재계산합니다. 이미 적용한 지원 제한/영구 제한은 소급 해제하지 않습니다.
- 운영사의 수동 해제는 사유/계정을 기록하고, 노쇼 횟수·활동 이력은 유지합니다. 다음 노쇼 때 누적 기준으로 다시 제한될 수 있습니다.

## XLSX

배송지 파일은 선정 후 주소를 등록한 참여자만 포함하며 수령인·우편번호·상세주소도 제공합니다. 파일의 `application_id`, `carrier`, `tracking_number` 열을 유지합니다. 송장번호와 전화번호는 텍스트 셀로 보존하세요. 업로드는 최대 2MB, 500행이며 모든 행이 유효해야 전체 반영됩니다. 다른 캠페인의 지원 ID, 중복 ID, 잘못된 상태를 포함하면 반영하지 않습니다. 압축 해제 크기와 엔트리 수에도 제한을 둡니다.

결과 XLSX에는 제출 URL·상태·Best·조회수·티어·동의 버전을 포함합니다.

## 검증

```bash
npm run typecheck
npm test
npm run test:browser
npm audit
```

브라우저 테스트는 Playwright를 사용합니다. 현재 환경의 `/usr/bin/chromium`을 자동 사용하며, 다른 경로는 `CHROMIUM_PATH`로 지정합니다. 로컬에 브라우저가 없으면 `npx playwright install chromium`으로 설치하세요. 테스트는 서버를 3102 포트에서 실행하고 종료합니다. 외부 이메일/SMS를 발송하지 않습니다.

서버 테스트는 소유권·상태 전이·마감·중복 완료·제재·정책·XLSX 등을 검증합니다. 브라우저 테스트는 가입부터 캠페인 종료까지, XLSX 다운로드/업로드, 관리자 정책/이력, 모바일 폭, 콘솔 오류, DB 백업 복구 데이터를 확인합니다.

## 데이터와 백업

- 기본 DB: `data/seoul-scent.db` (이전 YGSC DB와 별개)
- `DATABASE_PATH`: DB 경로. 시작 시 없는 디렉터리/테이블을 생성하고 스키마를 추가합니다.
- 사용자/배송지/동의/세션 데이터는 DB에 저장됩니다. DB와 백업은 외부 공개 디렉터리에 두지 않습니다.

```bash
npm run db:backup
# 특정 경로로 백업할 때
BACKUP_PATH=/secure/location/seoul-backup.db npm run db:backup
```

기본 백업 위치는 `data/backups/`이며 기존 파일을 덮어쓰지 않습니다. 운영 백업을 별도 보관소로 복제하고 정기 복구 연습을 수행하세요. 복구 시 서버를 멈추고 현재 DB와 WAL/SHM을 함께 보존한 뒤, 백업 파일을 새 DB 경로로 복사하여 `DATABASE_PATH`를 지정합니다. 복구 후 기존 세션은 관리자가 폐기하는 것이 권장됩니다.

## 배포 준비

```bash
npm ci --include=dev
npm run build
npm run start:prod
```

컴파일 결과는 `dist/server.js`입니다. `NODE_ENV=production`에서 Secure 쿠키를 사용하므로 HTTPS가 필요합니다. `APP_ORIGIN=https://실제서비스도메인`을 지정하면 프록시 뒤에서도 해당 출처의 요청만 허용합니다. 미지정 시 요청 Host의 HTTPS 출처를 기준으로 합니다. 공개 주소가 확정되면 명시적으로 설정하세요.

`seoul-scent/render.yaml`에는 `rootDir: seoul-scent`와 Node 24와 **유료 영구 디스크**를 사용하는 배포 초안을 준비했습니다. 배포하거나 요금제를 구매한 상태는 아닙니다. SQLite는 동일 DB를 공유하는 단일 서버 기준입니다. 복수 인스턴스로 확장하려면 DB 구조를 변경해야 합니다.

### 아직 외부 연동이 필요한 부분

- 이메일/SMS: 현재 **내부 알림만** 자동 생성합니다. 발송 업체·발신자 인증·API 자격증명이 필요합니다.
- 실시간 배송조회: 송장 표시까지 구현했습니다. 택배/배송조회 API 계약이 필요합니다.
- 공유 링크 공개 권한: 링크 형식과 사용자 확인을 검사합니다. 실제 공개 권한을 자동 확인했다고 표시하지 않습니다.
- SNS 조회수: 브랜드 입력값입니다. 자동 수집하려면 각 SNS의 승인된 API 접근이 필요합니다.
- 공개 운영 전 이메일 소유권 인증·비밀번호 재설정, 배포 환경의 IP 요청 제한, 개인정보 약관/보관 정책과 운영 모니터링을 준비해야 합니다.

저장소 루트의 `server.ts`, `vite.config.ts`, `wrangler.jsonc`, `DEPLOY.md`, `RENDER_DEPLOY.md`는 이전 YGSC 자료입니다. Seoul Scent의 실행 기준은 이 README와 `src/seoul/server.ts`입니다. 이전 Cloudflare 의존성과 실행 스크립트는 사용하지 않습니다.

## 폴더 분리 후 Render 연결

새 앱은 저장소의 `seoul-scent/`에 있습니다. 이 폴더만 설치·실행하세요.

- Blueprint 사용 시 설정 파일 경로: `seoul-scent/render.yaml`
- Web Service를 직접 만들 때 Root Directory: `seoul-scent`
- Build Command: `npm ci --include=dev && npm run build`

### 캠페인 링크와 모집 기간

캠페인 등록 시 선택 항목인 제품·브랜드 링크를 입력하면 상세 화면에서 새 탭으로 열 수 있습니다. 제품 소개와 가이드라인에 적힌 HTTP/HTTPS 주소도 클릭할 수 있습니다. 모집 시작일은 한국 시간 00:00부터, 모집 마감일은 해당 날짜 종료까지 적용됩니다. 시작 전에는 ‘모집 예정’으로 표시되고 지원할 수 없습니다.

상세 화면의 캠페인 편집에서 기존 캠페인의 링크와 일정을 변경할 수 있습니다. 모집 중에는 지원자가 있어도 일정을 변경할 수 있으며, 변경 시 진행 중인 지원자에게 알림이 전달됩니다. 기존 캠페인은 생성일을 모집 시작일로 보완하며 계정·지원·배송 데이터는 유지됩니다.

### 등록 후 캠페인 편집

### 한국어 / 영어와 선택적 초안 검수

로그인·가입 화면과 업무 화면 상단의 **Language**에서 한국어 또는 English를 선택합니다. 선택은 해당 브라우저의 쿠키에 1년간 저장되며, 메뉴·버튼·상태·안내는 준비된 번역을 사용합니다. 캠페인명·제품 소개·가이드라인·피드백·주소 등 사용자가 직접 작성한 내용은 원문을 유지합니다. 외부 번역 API 비용은 발생하지 않습니다. 번역 사전은 `public/translations.json`이고 빌드 시 `scripts/build-i18n.cjs`가 브라우저용 사전을 생성합니다.

캠페인 생성 시 **초안 검수 필요**를 해제하면 초안 마감일을 받지 않으며, 인플루언서는 선정 → 배송지 등록 → 배송 시작 → 최종 SNS 링크 제출 → 브랜드 완료 확인으로 진행합니다. 무가·유가 모두 검수 여부를 선택할 수 있습니다. 기존 캠페인은 검수 필요로 유지되며, 지원자가 생기거나 모집이 마감되면 검수 방식은 변경할 수 없습니다.

검수용 초안은 Drive·Dropbox·YouTube 등 임의의 HTTP/HTTPS 웹 링크를 허용합니다. 브랜드가 링크를 열 수 있는지 확인하는 체크박스는 유지합니다. `javascript:`, `data:`, 파일 경로 및 URL에 포함된 로그인 정보는 허용하지 않습니다. 링크를 서버에서 내려받지 않습니다. 최종 제출은 기존 SNS 게시물 URL 검증을 유지합니다.

### 캠페인 내용 영어 번역

영어 화면은 캠페인명·제품명·제품 소개·콘텐츠 가이드라인도 번역하며, 내 캠페인 카드와 참여 상세의 캠페인명도 동일한 영어 문구를 사용합니다. 한국어 원문과 편집 입력값은 보존합니다. 캠페인 생성/편집의 **English campaign content (optional)**에서 영어 문구를 직접 입력하면 자동 번역보다 우선합니다. 원문을 수정하면 해당 항목의 이전 번역과 직접 입력한 영어는 갱신 대상이 됩니다. 영어를 함께 새로 입력하면 새 문구를 사용합니다.

자동 번역은 인증키 없이 MyMemory 공개 번역 API (`api.mymemory.translated.net`)를 사용합니다. 공개 캠페인 문구만 전송하며, 계정 이름·연락처·주소·비공개 피드백은 보내지 않습니다. 번역 결과는 SQLite에 원문 해시별로 저장하고 동일 요청을 합칩니다. URL은 그대로 보존합니다. 서비스 일일 사용량 제한·장애 시 원문을 표시하고 번역 불가 안내를 제공합니다. 직접 영어 입력은 외부 서비스 제한과 관계없이 표시됩니다. 공개 서비스 품질/사용량이 필요하면 별도의 번역 제공자 계약과 인증 설정이 필요합니다.

단위 테스트는 번역 응답을 대체하여 캐시·동시 호출·원문 변경·링크 보존·실패 처리를 검증합니다. 브라우저 테스트는 브랜드가 입력한 영어로 상세와 카드/참여 화면 연결을 검증합니다. 외부 번역 API의 실시간 응답 검증은 해당 호스트에 접속 가능한 환경에서 별도로 수행합니다.

### 캠페인 사진

브랜드는 캠페인 생성/편집에서 사진을 최대 4장 첨부하고 삭제·교체할 수 있습니다. JPG·PNG·WebP 원본은 장당 20MB까지 선택할 수 있으며, 브라우저에서 긴 변 1600px 이하·350KB 이하의 JPG로 변환한 뒤 전송합니다. PNG의 투명 영역은 흰색으로 저장합니다. 서버는 장당 400KB 이하의 JPG 형식과 크기·캠페인 소유권을 확인합니다. 사진 변경은 캠페인 저장 시 적용됩니다. 종료된 캠페인은 기존 편집 정책에 따라 수정할 수 없습니다.

사진은 SQLite의 `campaign_images` 테이블에 저장하므로 기존 Render 영구 디스크와 DB 백업에 함께 포함됩니다. 별도 외부 저장소나 API 키는 필요하지 않습니다. 로그인한 사용자만 캠페인 상세에서 갤러리와 원본 크기 사진을 볼 수 있으며, 다른 브랜드의 접근은 기존 캠페인 권한 정책으로 제한합니다. 대용량 영상은 계속 공유 링크로 제출합니다.

### 신규 회원 홍보 인증과 브론즈 지원 자격

신규 인플루언서는 **기본 / Basic** 등급으로 시작합니다. 완료 캠페인이 없고 홍보 인증 승인을 받지 않은 회원은 캠페인을 볼 수 있지만 지원할 수 없습니다. 인플루언서 **내 프로필 → 브론즈 홍보 인증**에서 Seoul Scent 홍보 이미지와 `https://bit.ly/4glyo5O`를 게시물/스토리에 함께 올렸는지 확인하고, 게시물 링크 또는 스크린샷(둘 다 제출도 가능)을 제출합니다. 스토리는 만료될 수 있으므로 링크가 보이는 스크린샷을 권장합니다. 공개 링크를 자동으로 내려받거나 홍보 내용을 자동 판정하지 않습니다.

스크린샷과 공식 홍보 이미지는 브라우저에서 최대 1600px·350KB JPG로 변환하여 SQLite에 저장합니다(서버 400KB 제한). 스크린샷은 본인과 운영사만 볼 수 있으며 브랜드와 다른 인플루언서의 접근은 금지됩니다. 반려/재제출 자료와 운영사 검토 기록은 남습니다. 이메일 발송 없이 시스템 내부 알림으로 검토 결과를 전달합니다. 한국어/영어 화면을 제공합니다.

### 콘텐츠 파일에서 누락 회원까지 등록

이력 등록의 **계정이 없는 이메일은 신규 등록**을 선택하면 `인플루언서명`과 `이메일` 열로 새 회원을 만들고 같은 요청에서 완료 이력까지 등록합니다. 신규 계정 임시 비밀번호 기본값은 `0000`이며, 첫 로그인에서 비밀번호 변경이 필수입니다. 연락처·팔로워 수는 파일에 없으므로 추정하지 않고 본인이 프로필을 완성해야 캠페인 지원이 가능합니다. 같은 이메일의 기존 회원 정보·비밀번호·역할은 바꾸지 않습니다. 다른 역할의 이메일, 이름 형식 오류는 검토 대상으로 남깁니다. 업로드 미리보기에서 신규 회원과 완료 이력을 확인할 수 있으며, 반복 등록해도 계정과 횟수가 중복 생성되지 않습니다.

### 브랜드의 최종 선정

캠페인 지원자 목록에서 완료 횟수(과거 프로젝트 이력 포함), 진행 중 건수와 등급을 함께 확인하고 체크박스로 후보를 선택합니다. 선택은 해당 브라우저 탭의 임시 상태로 저장되어 탭 필터 변경이나 상세 검토 후 돌아와도 유지되며, 선택 자체로는 선정·알림·메일이 발생하지 않습니다. **최종 선정**에서 인원과 이름을 확인한 후에만 선택한 지원자를 확정하고 선정 메일을 발송 대기열에 넣습니다. 나머지 지원자는 그대로 미선정 상태입니다. 모집 정원·캠페인 소유권·현재 상태·제재를 서버에서 모두 확인하며, 한 명이라도 실패하면 전체 선정과 메일 등록을 취소합니다. 기존 발송 한도와 재시도 정책에 따라 메일을 순차 발송합니다.

화면의 ‘티어’는 ‘등급’으로 바꾸고 운영 메뉴는 **등급관리**로 표시합니다. 등급/참여 횟수 옆 **i** 버튼을 클릭하거나 키보드로 열어 계산 기준을 확인할 수 있습니다. 실버·골드·플래티넘 안내는 운영사의 현재 횟수 정책을 사용합니다.

### 인플루언서·등급관리 통합 화면

관리자 권한으로 `/admin/users`에 접속하면 전체 인플루언서 목록을 기본으로 표시합니다. 이름·이메일·연락처·SNS 검색, 등급과 검토 대기/지원 제한 필터를 사용하고 연락처·SNS·팔로워·등급·완료 횟수·진행 중 건수·노쇼 내역을 함께 확인할 수 있습니다. 참여 이력과 제재 검토, 홍보 인증 승인/반려, 회원·이력 엑셀 등록, 등급 기준 설정으로 연결됩니다. 계정 유형 필터로 브랜드·운영사 또는 전체 계정도 볼 수 있습니다. 지원 가능 집계는 비밀번호 변경·SNS 프로필·등급 자격·제재 조건까지 확인하며 회원 등록 후 목록과 집계를 갱신합니다. 관리 API는 이메일 문자열이 아닌 로그인 계정의 `admin` 역할로 권한을 확인합니다.


2차 프로젝트 신청서 가져오기는 관리자 전용 `/api/work/admin/projects/second/import`에서 XLSX를 검토(`dry_run: true`)한 후 등록합니다. 네 브랜드 아이디(varihope, airmood, teriv, livhamo)는 최초 생성 시에만 임시 비밀번호를 설정하며 기존 계정의 비밀번호는 유지합니다. 아이디 전용 브랜드 계정의 로그인 키는 users.email과 username에 저장되고, 실제 이메일이 없는 경우 계정 편집 및 관리자 목록의 이메일은 빈 값으로 표시합니다. 이메일을 나중에 등록해도 브랜드 아이디는 유지합니다. 일반 회원가입은 기존 이메일 방식을 유지합니다.

캠페인은 모집 인원 50명의 비공개 초안으로 생성합니다. 일정은 추정하지 않고 비워 두며, 브랜드 또는 관리자가 편집 화면에서 일정과 조건을 설정하고 `저장 후 캠페인 공개`를 선택하면 공개합니다. 공개 전에는 검색과 캠페인 상세에 인플루언서 접근을 허용하지 않으며 노쇼 처리를 차단합니다. 가져온 캠페인은 일정이 미정인 초안 상태에서도 먼저 선정할 수 있고 선정 안내가 발송됩니다. 이미 진행한 모집 기간을 지난 날짜로 저장할 수 있습니다. 모집 마감이 지난 캠페인을 공개하면 모집 마감 상태가 되며, 콘텐츠 제출 마감은 미래 날짜여야 합니다. 가져온 신청은 이메일로 연결하며 완료 횟수와 등급을 늘리지 않습니다. 원본 신청서에 없는 고화질 원본 제공 동의는 0으로 기록하며, 추가 동의 전에도 선정할 수 있지만 배송지 등록과 송장 처리는 차단합니다. 외부 신청자는 지원 또는 선정 단계에서 본인 참여 상세에서 추가 동의를 제출할 수 있습니다. 지원자 목록은 완료 참여 횟수가 많은 순서로 표시합니다. 형식 오류의 명단은 기본적으로 등록을 차단하고, 관리자가 `skip_invalid: true`를 지정했을 때만 이름/이메일 오류 행을 제외하고 유효한 행을 등록합니다. 검토 결과에 제외한 시트/행을 반환합니다.


관리자는 캠페인 카드의 `정원 편집` 또는 캠페인 상세의 `관리자 캠페인 관리`에서 일정과 별개로 선정 정원을 1~500명으로 변경할 수 있습니다. 기존 선정 인원보다 작게 줄이는 것은 차단합니다. 관리자 전용 캠페인 삭제는 확인 후 목록에서 제외하는 논리 삭제입니다. 참여 내역, 완료 횟수와 활동증명서 근거는 유지하고 삭제 이후 변경 작업·노쇼 처리·대기 선정 메일 발송은 중단합니다. 캠페인 삭제 시점과 운영사 계정은 감사 로그에 기록됩니다.

관리자는 인플루언서·등급관리에서 이력 보기 → 프로필 정보 수정으로 이름·연락처·대표 SNS 링크·팔로워 수를 편집할 수 있습니다. 관리자 전용 API `/api/work/admin/users/:id/profile`은 계정 이메일·비밀번호·권한·완료 횟수·등급·제재를 변경하지 않으며 수정자와 수정 항목을 감사 기록에 남깁니다.

대표 SNS 링크는 도메인 제한 없이 HTTP/HTTPS 웹 링크와 단축 링크를 허용합니다. 관리자 편집·본인 프로필·엑셀 가져오기와 지원 자격 확인에 같은 검증을 적용합니다.

관리자 전용 `DELETE /api/work/admin/users/:id`는 이름·이메일 확인값(`confirm_name`, `confirm_email`)이 일치하고 선정·활동 이력이 없는 인플루언서만 삭제합니다. 미선정 신청과 관련 세션·알림을 함께 제거하고 운영사 감사 기록을 남깁니다. 완료·선정·노쇼 이력, 기존 프로젝트 이력 또는 활동증명서가 있으면 삭제를 차단합니다.

관리자 전용 `PUT /api/work/admin/users/:id/email`은 기존 이메일 확인값(`confirm_email`)과 새 이메일(`email`)로 인플루언서의 로그인 이메일을 정정합니다. 기존 사용자 ID와 참여 이력을 유지하고 세션을 만료시키며, 미발송 메일의 수신 주소를 변경합니다.
